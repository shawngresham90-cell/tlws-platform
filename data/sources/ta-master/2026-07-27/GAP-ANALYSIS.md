# TA / Petro / TA Express — read-only gap analysis

**This is not an import.** It produces no SQL, no manifest and no approved row.
Official TA data is unreachable (`ACCESS-BLOCKED.md`), so there is no source of
record and nothing can be approved.

What it does: size the work a fresh official export will have to do, so the
request is specific and the effort is known before the file arrives.

Generated by `scripts/ta-gap-analysis.mjs`.

## What this changes about the request

Two things go into the TA data-access request because of this analysis:

1. **A `status` column is essential**, not optional. With 33 excess rows and no
   status field, closures are detectable only as absence between two dated
   exports — which means every export must be retained forever.
2. **A stable `site_id` is essential.** The reference has one and it is clean
   (354 unique). Reconciling 387 live rows against 354 official ones by name
   would be guesswork; by ID it is mechanical.

## What must not happen

- The 347 `unsupported` rows must **not** be imported, published, or counted
  toward any gate percentage.
- The 33 excess directory rows must **not** be unpublished or deleted on this
  evidence.
- No coordinate, space count, amenity or name from the reference file may be
  written to the directory.
