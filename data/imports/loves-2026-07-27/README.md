## Three separate authorizations

Insertion, enrichment and publication are **not one decision**. None has been
given.

1. **Insert** — adds unpublished rows. Reversible by deleting rows carrying
   `source = 'loves-master-2026-07-27'`, a marker nothing else sets.
2. **Enrich** — writes coordinates onto 62 existing rows, blank-only. Reversible
   by `geocode_source`.
3. **Publish** — the only step a driver can see. Canary first, verify, then
   per-state.

`CORRECTIONS.sql` is a **fourth**, and it changes rows this import does not own.

## Invariants this package does not bend

**Every inserted row is `is_published = false` and `is_featured = false`.**
`is_indexable` is never named in any statement, so it keeps its column default.

**The coordinate-collision guard is not weakened.** The map-pin rule instead:
the main `truck-stops` row for a site receives the coordinate, and the 62
colocated CAT scale / truck care / truck wash rows at the same address are
reconciled as service records with **no** coordinate. One site, one pin. See
`data/sources/loves-master/2026-07-27/COLOCATED-SERVICE-ROWS.csv`.
`VERIFY.sql` §5 fails if a store number ever has two mappable rows; §6 fails if
two distinct sites share a coordinate.

**Enrichment is blank-only and by exact id.** No update matches on business
name. A row with a coordinate already is skipped, not overwritten.

**Nothing is deleted by the forward path.** The only `delete` in the package is
in `ROLLBACK.sql` block 3, it can reach only rows this import created, and it
refuses while any target is published or featured.

**No attribute is invented.** Space counts, overnight flags, exit numbers and
coordinates are the operator's own values or they are null.

## If something goes wrong

Run `ROLLBACK.sql` blocks in order: unpublish → de-enrich → delete. Each is
independently guarded and each refuses rather than guessing. De-enrichment does
**not** revert `interstate` / `exit_number` / `parking_spaces` /
`overnight_parking`, because the forward statement wrote those with
`coalesce(existing, new)` and reverting to null could erase a pre-existing
value; revert those per-row from `ENRICHMENT-PLAN.csv` if needed.
