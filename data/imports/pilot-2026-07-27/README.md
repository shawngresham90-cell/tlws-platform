### The 17 zero-space locations

The operator states **0 spaces**. That is a stated fact, so it is stored as `0`,
not null. They belong in the directory as network truck stops and must **never**
be returned as parking or as a last-legal-stop recommendation. Enforced in three
places: the publish filter, the canary guard, and `VERIFY.sql` §3.

### Overnight permission

The export has **no overnight field**, and `overnight_parking` is
`NOT NULL DEFAULT false` — it cannot hold "unknown". Every imported row lands at
`false`, meaning **not confirmed**, not "prohibited". No statement in this
package ever writes that column. A positive space count confirms truck parking
for directory and map purposes only; restrictions and duration stay unknown.

## Matching evidence, in the order the brief requires

1. **Official store number**, same state. Authoritative, tried first.
2. **Address**, then **coordinate proximity (≤150 m)**, then **brand**, then
   state. Used only for directory rows the store number could not reach; 29 rows
   matched this way, 5 of them map pins.
3. A loose business name is **never** sufficient on its own.

Two guards keep the secondary pass honest. Brand family must agree, so a
Southern Tire Mart never becomes a Pilot Travel Center — third-party brands
(Southern Tire Mart, Speedway, Blue Beacon) carry their own numbering and are
excluded from the store-number join entirely, as is a name containing a CAT
Scale number. And an **ambiguous** match — more than one candidate — is refused
and quarantined rather than guessed.

## Invariants this package does not bend

**Every inserted row is `is_published = false` and `is_featured = false`.**
`is_indexable` and `overnight_parking` are never named in any statement, so both
keep their `NOT NULL DEFAULT false` — the rows are not manually indexable and
claim no overnight permission.

**The coordinate-collision guard is not weakened.** The map-pin rule instead:
the main `truck-stops` row for a site receives the coordinate, and the 92
colocated CAT scale / tire / wash / roadside rows at the same addresses are
reconciled as service records with **no** coordinate. One site, one pin.
`VERIFY.sql` §6 fails if a store number ever has two mappable rows; §7 fails if
two imported sites share a coordinate.

**Enrichment is blank-only, per field, and by exact id.** No update matches on
business name. Checked against the real current values — 73 rows already carry a
parking count and are not restaged; 2 already have coordinates and are skipped.

**Nothing is deleted or unpublished by the forward path.** The only `delete` is
`ROLLBACK.sql` block 3, it can reach only rows this import created, and it
refuses while any target is published or featured.

**No attribute is invented.** Space counts, coordinates, exits and brand names
are the operator's own values or they are null.

## Three separate authorizations

Insertion, enrichment and publication are **not one decision**. None has been
given.

1. **Insert** — adds unpublished rows. Reversible by deleting rows carrying
   `source = 'pilot-master-2026-07-27'`, a marker nothing else sets.
2. **Enrich** — writes coordinates onto 82 existing rows and a parking count
   onto 38, blank-only. Reversible by `geocode_source`.
3. **Publish** — the only step a driver can see. Canary first, verify, then
   per-state.

Closure review would be a **fourth**, and it changes rows this import does not
own.
